# OWASP ASVS 4.0.3 — V5.1.1 HTTP Parameter Pollution

## Objetivo

Implementar una defensa central contra HTTP Parameter Pollution (HPP), evitando que una misma clave escalar pueda aparecer varias veces en una petición y ser interpretada de forma diferente por distintas capas de la aplicación.

OWASP V5.1.1 exige defensas contra HPP (CWE-235).

## Antes

La aplicación utilizaba parámetros de entrada en distintos controladores mediante `$request->input()`, `$request->get()` y otros accesos. Aunque existen validaciones mediante Form Requests, no había una defensa transversal específica para parámetros HTTP duplicados.

Ejemplos encontrados durante la revisión:

- `app/Http/Controllers/ReservaController.php`: `search`, `perPage`, `fecha`, `reserva_id`.
- `app/Http/Controllers/ConsultaController.php`: `reserva_id`, `redirect_to_edit_consulta`, `veterinario_id`, `criterio`.
- `app/Http/Controllers/UserController.php`: `search`, `perPage`, `role_id`.
- Otros controladores de búsqueda utilizan `search`, `perPage` y `page`.

## Después

Se agregó:

`app/Http/Middleware/PreventHttpParameterPollution.php`

El middleware se registra globalmente en:

`bootstrap/app.php`

mediante `prepend()`, por lo que se ejecuta antes de los controladores.

### Comportamiento

Petición normal:

`/?search=Juan`

→ Permitida.

Petición contaminada:

`/?search=Juan&search=Pedro`

→ HTTP 400.

Colección legítima:

`/?servicios[]=1&servicios[]=2`

→ Permitida.

También se incorpora detección de claves duplicadas en JSON cuando el cuerpo bruto está disponible.

## Prueba manual recomendada

1. Solicitud normal:
   `GET /?search=uno`
2. Solicitud manipulada:
   `GET /?search=dos`
3. Solicitud contaminada:
   `GET /?search=uno&search=dos`

La tercera debe devolver HTTP 400.

## Nota sobre POST form-urlencoded

La detección de duplicados del query string es determinista porque se inspecciona el query string bruto. Para cuerpos `application/x-www-form-urlencoded`, PHP puede normalizar los parámetros antes de que Laravel reciba la petición, por lo que una auditoría de servidor/proxy debe complementar esta defensa cuando se requiera evidencia específica de duplicados POST.
